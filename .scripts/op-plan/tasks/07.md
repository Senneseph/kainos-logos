# Action Step 07 — Deterministic language kernel + CODEX lexicon (P1.03–P1.04)

> Self-contained: you need only `00-CONTEXT.md` + this file.

## Goal

A deterministic parser that turns restricted-English regex descriptions into the
dialect AST, plus the lexicon seeded into the CODEX (so *meaning* lives in the CODEX,
not in the parser).

## Prerequisites

- [ ] Step 06 done (dialect + emitter).

## Background

The kernel is the "language organ" (invariant #2): `text ↔ IR` only. For Phase 1 it is
**deterministic** (hand-written grammar) so the compositionality experiment isn't
confounded by an LLM's latent regex knowledge. The lexicon (what "hyphen"/"digit"
*mean*) goes in the CODEX, not in the parser — that's the whole point.

## Steps

### 1. `src/kainos/lang/kernel.py`

```python
@dataclass
class Interpretation:
    ir: object            # a regex dialect Node (later: generic SemanticIR)
    score: float
    unresolved: list[str]

class LanguageKernel(Protocol):
    def parse(self, text: str, context: dict | None = None) -> list[Interpretation]: ...
    def realize(self, ir, style: str | None = None) -> str: ...
    def propose(self, ir) -> list[dict]: ...
```

### 2. `src/kainos/lang/deterministic.py` — `DeterministicKernel`

Implement a small tokenizer + recursive-descent parser for this grammar (from
`plan/30-phases/phase-1-regex/spec.md` §1):

- **Clause templates:** `<anchor>`, `<quant> <class>`, `the literal <text>`,
  `a hyphen` / any bare content word (lexicon-ref, see below), `either <a> or <b>`,
  `a group of (…)`, `ignoring case`, `<connector> <clause>`.
- **Quantifier surface → value:** `one or more`→one_or_more; `zero or more`→zero_or_more;
  `optional|maybe|optionally`→optional; `exactly N | N`→exactly(N); `at least N`→at_least(N);
  `at most N`→at_most(N); `between N and M | from N to M`→between(N,M).
- **Class surface → node:** digit(s)/number(s)→digit; letter(s)→letter; word→word;
  whitespace/space(s)→whitespace; any/anything→any.
  **Disambiguation:** bare "number(s)" → `Literal` when a standalone numeral follows;
  else `Class(digit)`; if truly ambiguous → `UnresolvedRef` with both candidates.
- **Connectors:** `followed by|then|and|,` → sequence continuation; `or|either…or` →
  alternative.
- **Reference terms:** `thing`, `the … thing`, `it`, `that` → `UnresolvedRef(surface,
  candidates=["digit_class","numeric_literal",…])`.
- Anchors: `beginning/start of string` → Anchor(start); `end of string` → Anchor(end).
- `realize(ir)` = emit(ir) (reuse step 06 emitter).
- `propose(ir)` = `[]` for now (the reasoner proposes in step 08).
- **Lexicon-reference semantics (important):** the parser assigns **no character
  values**, ever. Class surfaces keep semantic class identity; a content word
  (`hyphen`, `dash`, …) is resolved at parse time by a **direct CODEX lexicon
  lookup** (exact `realizes_as` → `Literal(realization)`). A miss or an ambiguous
  hit yields `UnresolvedRef`, which the step-08 resolver handles by rotation or
  escalation. (Authoritative wording: `plan/30-phases/phase-1-regex/spec.md` §1.)

Keep it a pure function of text → AST; **do not** hard-code "hyphen means `-`" here.

### 3. Seed the lexicon into the CODEX

`src/kainos/regex/lexicon.py` — `seed(codex)`: add assertions (provenance
`Source(uri="seed_corpus", version="1")`, `status=established`) for:

```
"hyphen"       --realizes_as--> "-"
"digit"        --realizes_as--> "\d"
"letter"       --realizes_as--> "[A-Za-z]"
"word"         --realizes_as--> "\w"
"whitespace"   --realizes_as--> "\s"
"any"          --realizes_as--> "."
"start"        --realizes_as--> "^"
"end"          --realizes_as--> "$"
```

### 4. Tests

- `tests/lang/test_deterministic.py`: every clause template + every quantifier/class
  surface → expected AST node. Include "three digits, then a hyphen" → Sequence of
  Repeat(digit, exactly 3) then Literal("-") (the hyphen came from the lexicon, not the parser).
- **Lexicon↔emitter parity test:** for every seeded `realizes_as` target, the
  emitter's output for the corresponding node equals the CODEX realization — the
  CODEX is the single source of truth for what a term means (invariant #2); the
  emitter's built-in class table is held consistent by this test (spec §5).
- `tests/regex/test_codex_seed.py`: after `seed()`, query each class/literal and assert
  the realization; `dump()` shows `status=established` + `source=seed_corpus` on every
  seeded assertion (invariant #1).
