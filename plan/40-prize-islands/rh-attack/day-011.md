### The correction (most important line of the day)

An earlier draft of the `RhAttack/B0.lean` header carried a ground rule
I had *probed* and half-guessed: **“context-based implicit synthesis is
DISABLED in this toolchain (4.34.0-rc2); even `{n : ℕ}` does not
synthesize from the local context.”** That framing implied a *removed*
feature. Reading the reference manual shows it was a **misreading**, and
I have corrected the header:

- **“Namespaces and Sections”** (verbatim): “When the name of a section
  variable is encountered in a non-theorem declaration, it is added as a
  parameter … All section variables are added in the order in which they
  are declared, **before all other parameters**.” `variable (…)` is
  EXPLICIT; `variable {…}` is implicit. My original `sliceFin t ht`
  blocker (“expected Set ℂ”) was exactly this: an explicit
  `(Z : Set ℂ)` section variable made `sliceFin` silently become
  `sliceFin (Z : Set ℂ) (hFIN : …) (t : ℝ) (ht : …)` (verified by
  `#check`), so `sliceFin t ht` unified my `t : ℝ` with the FIRST
  argument `Z : Set ℂ`. Nothing was removed — the binder style was
  mis-read.
- **“Terms — Implicit Parameters”** (verbatim): ordinary implicits are
  values “that Lean should determine **via unification** … each call
  site should have exactly one potential argument value.” Implicits are
  **not** filled by scanning the local context for a constant of the
  right type. The manual’s own error example is the exact shape of my
  probe. The 4.33→4.34 release notes contain **no** entry removing such
  a feature.

Consequence (design): the state travels as the single explicit
`ZeroSet` argument of every def/theorem (the B4/E7a idiom). No reliance
on section-variable implicit threading. The file header now carries only
manually-quoted, verbatim-cited ground rules — no probe-guesses.

### New ground rules added (B-0 batch, joins §2)

- `simp only [lemma]` **does not unfold a context-local `let` def**
  under it to match; `dsimp only [theLet]` first, then `simp only
  [lemma]` (proven with a minimal 4-line repro before applying); local
  lets are not valid `simp`-set entries by name, while context-local
  defs *are* nameable in `dsimp`.
- Complex conjugation is `star`; `Complex.conj_re`/`conj_im` fire only
  after delta-reducing `star`: `simp only [star, …]`.
- `Finset.mem_filter` needs the `filter` constant to *appear* in the
  goal term; an `id (…)`/let wrapper must be `dsimp`ed away first; its
  `[DecidablePred p]` instance is filled automatically; nested filters
  reduce outer-first.
- `obtain`/`tauto` cannot see through Quot-based finset membership or an
  opaque local `let`; reduce with `dsimp`/`simp [Finset.mem_filter]`
  down to concrete `∧`/`∨` first. `tauto` does **not** apply equalities
  as rewrites — `simp [theEq]` first, `tauto` only for pure
  propositional residuals (e.g. a swap of disjuncts).
- `Finset.card_biUnion` takes **only** the pairwise-disjoint hypothesis
  (`s`/`t` are implicit). `even_two_mul` has no `Parity.` prefix; there
  is no `Nat.smul_eq_mul` (use `nsmul_eq_mul`); `List.map` (no
  `List.image`); `#eval!` when the file is `noncomputable` but the
  evaluated term is computable.
- `rw [hbe]` with `hbe : orb ρ = b` rewrites `orb ρ`→`b`; to go the
  other way write `rw [← hbe]` (a failed forward-direction rw cascade
  cost an hour of confusing “pattern not found” errors).
- A `have … by` block’s `dsimp at hx` does **not** leak out: the
  outer hypothesis keeps its original type after the subproof ends —
  each sibling bullet must re-reduce what it needs.
- **Module doc-string / header convention (new in 4.34):**
  `linter.style.header` wants `Copyright (c) YYYY` before the imports
  and the module doc-string as the first command after them; the rc2
  parser, however, **rejects** a doc-string immediately followed by
  `open`. Parseable layout used: `import → open → /-- doc (attached to
  the first decl) → …`, with a file-scoped
  `set_option linter.style.header false` + comment saying why.

## §5 What I would tell someone starting fresh

  payoff is an artifact outsiders can verify in one command — that is
