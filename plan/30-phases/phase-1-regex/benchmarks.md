# Phase 1 — Benchmarks & dataset

## Dataset

- **`data/regex/seed_corpus.jsonl`** — hand-authored `(description, expected_pcre,
  positive[], negative[])` tuples covering every operator in spec.md. ~40–80 items.
  This is the *only* thing the deterministic kernel is "trained" on (it's the
  grammar itself, made explicit).
- **`data/regex/compositional_set.jsonl`** — novel combinations of known operators,
  never present as a single seed example. Generated by a script from a
  cross-product of operators (seeded, reproducible).
- **`data/regex/vague_set.jsonl`** — deliberately underspecified descriptions for E1.4.
- **`data/regex/holdout_set.jsonl`** — a small set never used in development, for a
  final honest check.

## Metrics (from the document's own list)

| Metric | Definition |
|--------|------------|
| **Syntax** | Does the output compile? |
| **Semantic correctness** | Does it match the intended language (judge verdict)? |
| **Overmatching** | #invalid generated strings accepted (should be 0). |
| **Undermatching** | #valid generated strings rejected (should be 0). |
| **Generalization** | Accuracy on novel descriptions. |
| **Compositionality** | Accuracy on unseen operator combos. |
| **Memory** | Knowledge retained after restart. |
| **Updating** | Can a term's meaning change without retraining? |
| **Contradiction handling** | Conflicting definitions preserved (P6), not averaged. |
| **Abstention** | Correct "I don't know / clarify" on vague input. |

## A/B protocol (E1.5)

1. Fix seed data (same for both). For Model A, this is training data. For Model B,
   it is loaded as CODEX assertions (provenance: `source=seed_corpus`).
2. Hold out `compositional_set` and `vague_set`.
3. Evaluate both on identical inputs, identical judge.
4. Report accuracy, abstention, and a per-item diff table in `results.md`.

## Reproducibility

- All generators seeded; all results written to `results/phase-1/*.json` with a
  `config` block (seed, commit hash, dataset hash).
- `make bench` runs the full suite and regenerates `results/phase-1/SUMMARY.md`.
