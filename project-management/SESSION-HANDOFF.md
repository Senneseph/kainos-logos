## 5. E2 design decisions (why each experiment is shaped this way)

- **E2.1**: 500 games/side, targets = seeded `random.Random(seed).choice`
  over all 149 (losses count at the full budget 20 in the median). System =
  GreedyIGPolicy; baseline = `RandomQuestioner(questions, seed=1000+i)`
  (fresh seeded deck per game, each question once, then the game guesses).
  Threshold: system median ≤ 0.8× baseline median AND win-rate ≥. Reality
  check from step 14: only 20/149 concepts are vector-identifiable, so
  win-rates are capped (~system wins all 20-unique + ~half of twin pairs via
  the min(H) fallback guess; random barely wins). The GAIN (median ~4-6 vs
  ~17+) is the headline.
- **E2.2**: the CODEX starts **EMPTY** (that's the point — a pre-seeded
  world has coverage 1.0 with no room to rise). 200 seeded games; after each:
  `consolidate` + `detect_dimension` for every `sometimes` property seen.
  Samples every 25 games: coverage_mean (store.coverage over all 149),
  unknown_cells_remaining (1490 = 149×10 − known (concept,prop) cells),
  sometimes-assertion count, n_dimensions. Pass = coverage monotone ↑ AND
  unknown monotone ↓ AND strict end-to-end delta. The mechanism that makes
  coverage rise: first visit per concept = unverified candidates (coverage 0
  for those cells); a SECOND visit consolidates a duplicate → the duplicate
  verifies against the established sibling → promoted with
  provenance.verified=True → coverage rises per repeat. With 200 games over
  149 concepts, most concepts are visited 1–2× — verify the delta is
  significant before committing; if coverage_mean is stuck (e.g. 0.1 → 0.11),
  bump KAINOS_E2_SEQ (document the run size in the result config).
- **E2.3**: set1 (40, learned & consolidated into a store) → `store.dump()`
  → fresh `InMemoryCodexStore` filled via `Assertion.from_dict` for each
  dumped assertion (true restart, same as E1.3) → set2 (30 held-out,
  disjoint split via `random.Random(13).sample(ids, 149)`). Metric: median
  ORACLE QUERIES per set-2 game with `CodexAnswerSource(store2)` vs with an
  empty codex (both count only world queries; codex answers are free). The
  codex answers from learned assertions of ANY status (established
  preferred). Expect ~25-30% query saving (40/149 concepts in every H get
  answered from memory). Also asserts `learned_present_after_restart`.
  QUESTION COUNTS are identical by construction (same answer values) —
  reported honestly, not used as the pass metric.
- **E2.4**: holdout = 12 concepts (seed 99) sampled from the 20
  vector-identifiable ones (unique conjunction of 10 properties + category);
  recognition = exact conjunction match over the corpus (the CODEX seed is
  the "learned property base"); labels given to the recognizer: 0; baseline
  (label-guesser with 0 labels) = 0.0 → accuracy 1.0 ≥ 0.7. Per-target
  evidence (conjunction_size, guess) is in the JSON.
- **E2.5**: small injected world (bear hibernates=yes, polar_bear
  hibernates=no; established, provenance `e2.5_injection/1`, a local
  `q_hibernates` question passed via `consolidate(..., extra_questions=...)`).
  A "game" then claims polar_bear hibernates=yes → consolidate → disputed
  pair → `detect_dimension(store, "hibernates")` → NEW term
  `dim:hibernates` (kind=dimension, registered via the
  `<prop> --declares_dimension--> dim:<prop>` assertion), both assertion
  values retained (`hibernates=no` and `hibernates=yes`), each under a
  distinct context `{dimension, value}`, pair reconciled to established,
  disputed_after == 0. Threshold met iff all of that — it is.
